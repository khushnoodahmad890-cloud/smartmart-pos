--------------------------------------------------------------------------------
1. PROJECT OVERVIEW
--------------------------------------------------------------------------------
SmartMart POS is a full-stack, production-ready Point of Sale, Billing,
Inventory and Business Management platform built for retail stores,
supermarkets, pharmacies, restaurants, clothing stores, electronics shops,
grocery stores and wholesale businesses.

It is a complete commercial software product — not a demo or CRUD tutorial —
and ships in THREE deployment editions from a single codebase:

  1. WEB EDITION (single business)  — classic client/server deployment
  2. SAAS EDITION (multi-tenant)    — one server hosts unlimited stores,
                                      each with its own isolated database
  3. DESKTOP EDITION                — downloadable installer (Windows .exe,
                                      Linux AppImage, macOS DMG) with an
                                      embedded PostgreSQL database; runs
                                      100% locally with no internet required

The platform includes a built-in subscription system (Basic / Standard / Pro)
with server-enforced feature gating, card checkout, and offline cryptographic
license keys for desktop sales.

3. DATABASE ARCHITECTURE
--------------------------------------------------------------------------------
30+ normalized PostgreSQL tables with primary/foreign keys, unique
constraints, timestamps and indexes on all frequently searched fields
(barcode, SKU, product name, invoice number, customer phone):

  users, roles, permissions, role_permissions, branches,
  categories, brands, units, products, product_barcodes,
  inventory, inventory_movements, product_batches,
  customers, suppliers,
  sales, sale_items, payments, returns, return_items,
  purchases, purchase_items, purchase_returns, purchase_return_items,
  quotations, held_sales, shifts, cash_movements,
  expenses, promotions, audit_logs, notifications, settings, counters,
  subscriptions, billing_invoices, refresh_tokens, password_resets,
  api_keys, webhooks, tenants (control DB, SaaS mode)

Data-integrity guarantees:
  - Every financial operation (sale, return, cancellation, purchase,
    receiving, payment) runs inside a DATABASE TRANSACTION with row
    locking (SELECT ... FOR UPDATE) — no partial writes, ever.
  - Stock can never go negative unless explicitly enabled by the admin.
  - Financial records are never deleted: cancellations and returns are
    compensating entries; products are soft-deleted.
  - Unique sequential document numbers via an atomic counters table:
    INV-2026-000001 (sales), PUR (purchases), RET (returns),
    PRET (purchase returns), QUO (quotations), SUB/LIC (billing).
  - Weighted-average product costing updated on every goods receipt,
    so COGS and profit are always accurate.

4. USER ROLES & PERMISSIONS
--------------------------------------------------------------------------------
  - Role-based access control with 24 granular permission codes
    (view_dashboard, create_sale, process_refund, edit_inventory,
    manage_users, manage_settings, manage_billing, view_audit_logs, etc.)
  - Built-in system roles: Super Admin, Manager, Cashier
  - Custom roles can be created and their permissions edited from the UI
    (visual permission-matrix editor grouped by category)
  - Permissions are enforced ON THE SERVER per route; the UI additionally
    hides/locks what the user cannot access
  - Cashiers see only their own transactions; sensitive admin areas
    are blocked (verified with automated tests)
  - Disabling a user instantly revokes their refresh tokens/sessions

--------------------------------------------------------------------------------
5. AUTHENTICATION & SECURITY
--------------------------------------------------------------------------------
  - JWT access tokens (short-lived) + rotating refresh tokens; reuse of a
    rotated refresh token is rejected
  - bcrypt-hashed passwords (never stored or returned in plain text)
  - Forgot/reset password flow (SMTP email in production; on-screen token
    in demo mode)
  - Cashier PIN quick-switching: 4–6 digit PIN keypad at the POS to swap
    users in seconds without a full logout
  - Login rate limiting (30 attempts / 15 min) + global API rate limit
  - 100% parameterized SQL (SQL-injection safe)
  - CORS configuration, environment-variable secrets, production error
    messages never leak internals
  - Complete audit log: every important action recorded with user, action,
    description, IP address and timestamp (login, sales, refunds, stock
    adjustments, settings/permission changes, license activation...)
  - Audit-log retention policy with one-click purge

6. POS TERMINAL (THE CORE)
--------------------------------------------------------------------------------
Layout: product grid + search + category filters on the left; cart,
customer, totals and payment on the right. Designed for speed.

Barcode & scanning:
  - USB/keyboard barcode scanners (dedicated always-focused input field)
  - Camera scanning via phone/tablet (html5-qrcode)
  - SKU lookup, unknown-barcode / inactive / out-of-stock handling
  - Scan SOUNDS: beep on success, buzz on unknown barcode, chime on sale
    completion (WebAudio, toggleable)
  - WEIGHT/SCALE BARCODES: EAN-13 "PP IIIII WWWWW C" labels resolve to the
    product + embedded weight; price auto-computed per kg (prefix
    configurable) — essential for grocery/butcher/produce
  - EAN-13 barcode GENERATION with valid check digits, and printable
    barcode LABELS (JsBarcode) with business name + price

Cart & pricing:
  - Quantity controls, line discounts and order discounts — both as fixed
    AMOUNT or PERCENTAGE
  - Automatic PROMOTIONS applied while scanning (see section 12)
  - Wholesale PRICE TIERS: wholesale-flagged customers automatically get
    wholesale prices
  - Tax modes: EXCLUSIVE (added on top) or INCLUSIVE (extracted from price)
  - HOLD / RECALL (park) sales — stored server-side so any terminal can
    recall them; labeled ("customer in blue shirt")
  - Cart persists in localStorage — survives refreshes and crashes

Payments:
  - Cash (with change calculation + quick-amount buttons), card, bank
    transfer, mobile wallet
  - SPLIT PAYMENTS: any combination in one sale (e.g. cash + card + credit)
  - CREDIT SALES: unpaid remainder goes to the customer's account balance;
    received later against the specific invoice
  - LOYALTY POINTS as a payment method (redeem at configurable value)

Receipts & sharing:
  - Thermal receipt layouts (80mm and 58mm) with business logo
  - Print, download, server-generated A4 PDF invoice (pdfkit)
  - EMAIL receipts (SMTP) and WHATSAPP receipt sharing (pre-filled message
    to the customer's number)
  - Receipt customization: show/hide logo and tax breakdown, custom footer

Cashier UX:
  - Keyboard shortcuts: F1 help, F2 search, F4 customer, F6 discount,
    F7 hold/recall, F8 payment, F9 complete, Esc close, Enter confirm
  - Command palette (Ctrl/Cmd+K): jump to any page, product, invoice or
    customer from one box
  - Walk-in customer default; inline new-customer creation
  - Kitchen order toggle (restaurant mode)

CUSTOMER DISPLAY (second screen):
  - /customer-display route opens on a second monitor/window and mirrors
    the cart LIVE (BroadcastChannel + storage events): items, savings,
    total, then change due + thank-you screen after payment

OFFLINE-FIRST:
  - Connection status indicator
  - If the network drops, completed sales are QUEUED locally (localStorage)
    and automatically synced in order when the connection returns
  - Desktop edition works with no internet at all

8. INVENTORY MANAGEMENT
--------------------------------------------------------------------------------
  - Real-time stock per branch, stock value (at cost) and retail value
  - Low-stock and out-of-stock dashboards with status badges
  - Stock adjustments: add / remove / record damaged / set exact quantity
    (reconciliation) — a REASON is required and everything is audited
  - Branch-to-branch stock TRANSFERS
  - Complete MOVEMENT HISTORY: every change shows product, quantity,
    previous stock -> new stock, movement type (opening, purchase, sale,
    return, adjustment, damage, transfer in/out, purchase return),
    reference document, user, reason and timestamp
  - BATCH & EXPIRY tracking (pharmacy/grocery): batch number + expiry date
    captured at goods receipt, FEFO (first-expiry-first-out) depletion on
    sale, "expiring stock" report with day-window filters
  - Automatic low-stock/out-of-stock notifications when thresholds are
    crossed

9. SALES, RETURNS & CASH CONTROL
--------------------------------------------------------------------------------
Sales history:
  - Search by invoice/customer, filter by status, payment method and date
    range; CSV export; view/print/PDF any invoice
  - Sale CANCELLATION (permission-gated): restores inventory, reverses
    customer credit/points, preserves the financial record

Returns & refunds:
  - Find invoice -> select items & quantities -> reason -> refund
  - Partial and full returns; refunds proportional to what was actually
    paid (including line discounts and tax)
  - Inventory automatically restored; original sale marked
    partially_returned / returned — never deleted
  - Large-refund notifications for admins

Shifts & cash drawer:
  - Open shift with a counted float
  - Cash IN/OUT during the shift with mandatory reasons
  - Sales auto-attach to the cashier's open shift
  - Close shift with counted cash -> Z-REPORT: expected vs counted,
    over/short, takings by payment method, cash movements list
  - Printable Z-reports + full shift history

10. CUSTOMERS (CRM) & SUPPLIERS
--------------------------------------------------------------------------------
Customers:
  - Auto-generated customer codes, contact details, notes
  - Total purchases, order count, purchase history, returns history
  - CREDIT (receivables) balance with "receive payment" against specific

11. PURCHASING
--------------------------------------------------------------------------------
  - Purchase orders: pick supplier, add products with quantities and unit
    costs, pay fully / partially / later
  - Receive immediately or as an open PO; FULL or PARTIAL receiving
    (receive 80 of 100 units; status: ordered -> partially_received ->
    received)
  - Optional batch number + expiry date per received line
  - Goods receipt updates stock AND the product's weighted-average cost
    (accurate COGS forever after)
  - PURCHASE RETURNS to supplier: stock decreases, supplier balance
    decreases; full history
  - Outstanding balances per purchase and per supplier; payment recording

12. PROMOTIONS ENGINE
--------------------------------------------------------------------------------
  - Promotion types: % off a specific product, % off an entire category,
    and BOGO (Buy X Get Y free of the same product)
  - Optional start/end dates; pause/activate toggle
  - Evaluated automatically at the POS while scanning — the best applicable
    promotion per line is applied as a discount with a toast
    ("Weekend Sale applied — saved $1.20")
  - All promotion discounts flow through the normal validated sale path

13. QUOTATIONS & KITCHEN MODE
--------------------------------------------------------------------------------
Quotations:
  - Build a quote (customer, lines, custom prices, validity date)
  - Statuses: open / converted / expired / cancelled
  - One click loads the quote into the POS; completing payment marks it
    CONVERTED and links it to the resulting invoice

Kitchen display (restaurant mode, toggle in Settings):
  - POS gets a "Kitchen order" switch
  - /kitchen page shows a live order queue (order age, items) updated in
    REAL TIME via Server-Sent Events
  - Status flow: pending -> preparing -> ready

--------------------------------------------------------------------------------
14. EXPENSES & FINANCE
--------------------------------------------------------------------------------
  - Expense tracking with categories (rent, electricity, internet,
    salaries, transportation, maintenance, marketing, other), payment
    method, date, creator; filtered totals
  - TRUE PROFIT & LOSS:
        Revenue (net of refunds)
      − Cost of Goods Sold (weighted-average cost)
      = Gross Profit
      − Operating Expenses
      = NET PROFIT (+ profit margin %)
    Profit is NEVER computed from selling price alone.
  - Tax collected, discounts given and refunds reported separately

  - In-sale gating: points payments, wholesale pricing and kitchen orders

OFFLINE LICENSE KEYS (desktop sales):
  - Format: SMPOS-<payload>-<signature>, Ed25519-signed
  - The app ships only the vendor PUBLIC key: keys verify fully offline
    and cannot be forged; tampering fails the signature check
  - Vendor CLI: npm run keygen -- --plan pro --months 12 --customer "Name"
    (also --forever for perpetual licenses)
  - Expired keys rejected; expiry drops the install to Basic features
  - Activation recorded as a LIC- invoice + audit entry
  - UI: "Have a license key?" activation card on the Billing page

17. MULTI-TENANT SAAS MODE
--------------------------------------------------------------------------------
  - Enabled with MULTI_TENANT=true (+ CONTROL_DATABASE_URL)
  - DATABASE-PER-TENANT isolation: every store gets its OWN PostgreSQL
    database — the strongest isolation model; cross-tenant data leaks are
    architecturally impossible
  - Self-serve public SIGNUP on the login screen ("Create your store"):
    provisioning automatically creates the database, runs schema +
    4 migrations, seeds roles/permissions, creates the owner account and
    starts the 14-day Pro trial — in one request
  - Requests carry an X-Tenant store-code header; middleware resolves the
    tenant and routes ALL queries through AsyncLocalStorage — zero changes
    were needed in any controller
  - Per-store subscriptions, invoice numbering, feature gates, limits —
    fully independent (verified: one store on Basic gets 402s while
    another store stays Pro)
  - Signup rate limiting; duplicate store codes rejected; provisioning is
    rolled back (database dropped) if any step fails
  - Single-tenant and desktop modes are completely unaffected (default)

25. KEY BUSINESS RULES IMPLEMENTED
--------------------------------------------------------------------------------
  - Stock cannot go negative unless explicitly enabled by the admin
  - Returned products increase stock; cancelled sales reverse inventory
  - Purchases increase stock; purchase returns decrease it
  - Every inventory adjustment requires a reason and creates an audit record
  - Completed financial transactions are never hard-deleted
  - Every financial transaction has a timestamp and a responsible user
  - Invoice numbers and barcodes are unique (DB-enforced)
  - Product cost is stored and maintained (weighted average) for true profit
  - Discounts and taxes are calculated consistently everywhere
  - Deleted products are soft-deleted so history remains intact
